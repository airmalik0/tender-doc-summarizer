# Тендерный суммаризатор

Сервис извлекает из документации госзакупок структурированную выжимку: **сумму
контракта, сроки выполнения, ключевые требования к исполнителю и список штрафов**.

Решение тестового задания №1. Описание логики и алгоритма — в
[SOLUTION.md](SOLUTION.md).

Главное отличие от «отправить PDF в модель и вернуть ответ»: каждое извлечённое
значение сопровождается **цитатой из документа с номером страницы**, и эта цитата
автоматически проверяется поиском по исходному тексту. Ключевые суммы
дополнительно сверяются с независимым парсером на регулярных выражениях. В ответе
видно, где сервис уверен, а где нет.

---

## Быстрый старт

```bash
git clone <url-репозитория>
cd tender-doc-summarizer
docker compose up --build
```

Открыть **http://localhost:8000** — там интерфейс с перетаскиванием файла и
кнопками демонстрационных документов. Документация API — на `/docs`.

**Ключ не обязателен.** Без ключа сервис поднимется и будет разбирать документы
детерминированными правилами — это видно в интерфейсе и в поле `warnings` ответа.
Чтобы включить полноценное извлечение через LLM:

```bash
cp .env.example .env
# вписать ANTHROPIC_API_KEY, дальше:
docker compose up --build
```

Если порт 8000 занят: `PORT=8090 docker compose up --build`.

### Без Docker

```bash
make install        # виртуальное окружение и зависимости
cp .env.example .env
make run            # http://localhost:8000
```

Для распознавания сканов нужен `tesseract` с русским пакетом (в образе он уже
есть):

```bash
brew install tesseract tesseract-lang            # macOS
apt-get install tesseract-ocr tesseract-ocr-rus  # Debian/Ubuntu
```

Без него сервис работает, но документы без текстового слоя вернут ошибку
`empty_document`.

### Проверить, что всё работает

```bash
make smoke     # health + разбор демо-документа с выводом ключевых полей
make test      # 107 тестов, без сети и без ключей
make lint      # ruff, black, mypy
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/v1/summarize` | Разобрать загруженный PDF (`multipart/form-data`, поле `file`) |
| `POST` | `/api/v1/summarize/sample?name=…` | Разобрать документ из папки `samples/` |
| `GET` | `/api/v1/samples` | Список демонстрационных документов |
| `GET` | `/api/v1/health` | Состояние сервиса: провайдер, модель, доступность OCR |
| `GET` | `/docs` | Swagger со всеми схемами |
| `GET` | `/` | Веб-интерфейс |

У `summarize` есть параметр `use_cache=false` — принудительно разобрать заново.

Ошибки приходят в едином формате:

```json
{ "code": "pdf_parse_error",
  "message": "Содержимое файла не похоже на PDF: отсутствует сигнатура %PDF-.",
  "details": { "filename": "документ.pdf" },
  "request_id": "a00f1802" }
```

## Демонстрационные документы

В `samples/` лежат три файла, покрывающие разные случаи. Они генерируются
скриптом (`make samples`), а не лежат непрозрачными бинарниками: тексты
синтетические, но собраны по структуре реальной документации 44-ФЗ — те же
разделы и те же формулировки про пени и штрафы из ПП РФ № 1042.

| Файл | Что показывает |
|---|---|
| `tender-44fz-remont-krovli.pdf` | Электронный аукцион, 4 страницы: этапы работ с датами, дополнительные требования, полный набор мер ответственности |
| `tender-44fz-postavka-oborudovaniya.pdf` | Запрос котировок: относительный срок «в течение 45 дней, но не позднее …», обеспечение не установлено |
| `tender-scan-postavka-kanctovarov.pdf` | **Скан без текстового слоя** — проходит через OCR |

## Настройки

Все параметры читаются из окружения или `.env`, полный список с пояснениями — в
[.env.example](.env.example). Самое нужное:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `LLM_PROVIDER` | `auto` | `auto`, `anthropic`, `openai`, `gemini`, `offline`. `auto` берёт первого провайдера с ключом, без ключей уходит в `offline` |
| `ANTHROPIC_API_KEY` | — | Ключ основного провайдера |
| `ANTHROPIC_MODEL` | `claude-opus-5` | Можно поставить модель подешевле и побыстрее |
| `ANTHROPIC_EFFORT` | `medium` | `low`…`max` — глубина рассуждений и расход токенов |
| `OCR_ENABLED` | `true` | Распознавание страниц без текстового слоя |
| `OCR_LANG` | `rus+eng` | Языки tesseract; отсутствующие пакеты отбрасываются автоматически |
| `MAX_UPLOAD_MB` | `25` | Лимит размера файла |
| `MAX_PAGES` | `400` | Лимит страниц |
| `CHUNK_CHARS` | `14000` | Размер фрагмента для модели |
| `MAX_CHUNKS` | `12` | Предел фрагментов на документ |
| `CACHE_ENABLED` | `true` | Кэш разборов по содержимому файла |

Поддержаны три провайдера. Anthropic — основной и проверенный вживую; OpenAI и
Gemini реализованы через тот же контракт и ту же схему. Модели у них заданы
консервативными значениями по умолчанию (`gpt-4o`, `gemini-2.5-flash`) — под свой
доступ поменяйте `OPENAI_MODEL` / `GEMINI_MODEL`.

**Сколько это стоит и сколько ждать.** Документ на 4 страницы — около 9 тысяч
входных и 5 тысяч выходных токенов, два запроса к модели, 45–75 секунд на
`claude-opus-5`. Повторный разбор того же файла отдаётся из кэша за миллисекунды.
Модель подешевле уменьшает и время, и стоимость.

## Структура проекта

```
app/
├── api/              маршруты, зависимости, единый формат ошибок
├── core/             конфигурация, доменные исключения, логирование
├── models/           схемы: отдельно для модели, отдельно для ответа API
├── services/
│   ├── pdf/          извлечение текста, OCR
│   ├── llm/          контракт провайдера, 4 реализации, генератор JSON Schema
│   ├── extraction/   нарезка, промпты, правила, слияние, сверка цитат, сборка
│   └── cache.py      кэш разборов
└── web/index.html    интерфейс без внешних зависимостей

tests/                107 тестов, без сети и без ключей
samples/              демонстрационные PDF
scripts/              генератор демонстрационных документов
```

## Разработка

```bash
make help      # список команд
make install   # окружение и зависимости
make run       # локальный запуск с автоперезагрузкой
make test      # тесты
make lint      # ruff + black + mypy
make format    # автоформатирование
make samples   # пересобрать демонстрационные PDF
make up/down   # Docker
```

CI прогоняет линтеры, тесты и отдельным джобом собирает образ, поднимает его и
разбирает демонстрационный документ через HTTP — без ключей, на правилах,
поэтому весь путь от загрузки PDF до готового JSON проверяется целиком.
